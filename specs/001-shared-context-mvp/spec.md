# 001：本机共享上下文 MVP 规格

- 项目：`shared-ai-context`
- 日期：2026-11-09
- 状态：规格基线；实际实现与验收证据见 [验收记录](acceptance.md)
- 范围：单用户、本机编程 agent、显式操作、精简记录
- 实施前提：[团队计划](../../docs/TEAM.md) 已获用户确认，按文档基线、契约评审和分工推进；[AGENTS.md](../../AGENTS.md) 定义四条用户硬规则。

## 1. 问题与目标

用户在不同编程 agent 或聊天之间切换时，需要重复介绍任务目标、约束、进度和已有结论。完整聊天搬运还会带入无关信息与过时判断。

本工具提供可持久化、可定位的精简上下文记录，让用户能明确保存、读取和交接任务，并查看此前共享过的内容。优先保证原理简单、操作明确、结构可理解。

## 2. 需求来源与设计选择

| 类别 | 内容 |
| --- | --- |
| 用户已确认 | 个人使用；本机编程 agent；明确要求时触发；历史保存精简共享和交接记录 |
| 用户已要求 | 广泛接入、少污染上下文、指令精确、轻量持久化、共享读写、交接、历史；模块清晰、代码优雅；避免过度设计 |
| 用户可接受 | SQLite 存储 |
| 当前设计选择 | Python、SQLite、CLI 先行；MCP 作为可选后续入口；具体接口见设计 |

此处“广泛接入”的当前范围是有能力调用所选本地入口、并具有相应访问权限的编程 agent。它不承诺任意网页聊天或受限宿主都能直接接入。

## 3. 术语

| 术语 | 含义 |
| --- | --- |
| 会话 Session | 一件持续进行的任务；不等同于某个 agent 的原生聊天 |
| 记录 Record | 一次明确保存的独立内容，具有稳定标识、时间和来源元信息 |
| 共享 Share | 保存可独立理解的精简资料，可以只覆盖一个问题或结论 |
| 交接 Handoff | 为接续任务保存的一条记录，正文适合说明目标、进度、未解决事项和下一步 |
| 引用 Reference | 能准确定位记录的会话 ID 与记录 ID |

## 4. 功能需求

### FR-01：本地持久化

工具的存取过程必须在本机完成，不依赖网络或外部模型。操作完成并重新启动入口后，已保存的会话和记录仍然可读。工具不限制 agent 为其原本任务使用其他能力。

### FR-02：显式参与

接入说明应要求 agent 仅在用户明确要求使用本工具共享、交接或接续时调用。工具不自动采集原始聊天，不监控 agent，不在启动时自动读取或注入历史正文。

本工具不实现自然语言意图识别，也不声称能验证每次调用是否由人类发起。显式触发约定由接入说明及宿主使用方式落实。

### FR-03：明确定位会话

用户可以创建有标题的会话、查看会话列表，并用稳定标识选择会话。项目路径可以作为定位辅助信息。

读写操作必须明确携带会话标识。不设置所有 agent 共用的“当前会话”，不根据标题近似匹配或当前工作目录静默选择目标。

### FR-04：追加保存记录

用户可以在指定会话内保存共享或交接记录。记录包含标题、用途、Markdown 正文、保存时间和可选来源 agent 名称。

每次保存产生新记录和稳定引用。首版不提供修改、覆盖或删除历史记录的操作。普通共享不要求填写完整交接模板。

来源 agent 名称是说明信息，不是经过认证的身份。

### FR-05：按范围读取

会话列表和历史列表只返回定位所需元信息，不默认返回正文。列表默认最多返回 20 项，可明确调整数量。

读取正文时必须指定会话 ID 和记录 ID，且记录必须属于该会话。只返回目标记录，不自动附加其他记录、其他项目或原始聊天内容。

首版不将“最近保存的一条”解释为“已整合的完整任务状态”。

### FR-06：交接可接续

交接与普通共享使用相同存储机制。交接完成后返回确切引用和可复制的读取提示，方便用户交给另一个 agent。

交接正文建议包含用户目标与约束、已确认事实和决定、当前进度与验证情况、未解决问题、建议下一步及关键引用。内容由当前 agent 按用户指令整理，工具不调用额外模型生成摘要，也不强制正文满足复杂字段结构。

保存交接不会自动启动其他 agent、派发任务或执行记录中的命令。

### FR-07：历史保留与隔离

同一会话的多条记录应各自保留并可单独定位。不同会话的记录不得因读取或写入操作混入彼此结果。

多个 agent 分别保存内容时，不得静默覆盖已成功保存的记录。存储成功不代表内容已合并、冲突已解决或已经形成共同结论。

### FR-08：准确反馈

不存在的会话或记录、空标题或正文、无法持久化等情况必须明确返回失败，不返回伪造的成功引用。

工具只对实际成功提交的记录报告保存成功。失败时不切换到另一数据库，不自动改写或丢弃用户内容。无需承诺调用中断情况下的自动重试或恰好一次写入。

## 5. 质量要求

### QR-01：小接口与清楚职责

核心对外只暴露创建会话、列出会话、追加记录、列出记录、读取记录等少量操作。入口处理参数和呈现，核心统一行为，存储隐藏 SQL 和事务。依赖保持单向。

### QR-02：规则只有一个归属

CLI 作为当前外部入口，负责参数、正文和数据目录的输入校验。内部依据已校验输入、类型标注与调用契约工作，不重复进行语法、非空、数量或用途检查；类型标注本身不提供运行时强制。

会话存在性、记录归属、标识与时间生成、查询范围由共用核心处理。SQLite 外键保障数据完整性。预期入口、业务和存储失败在 CLI 集中转换成用户输出，内部不逐层捕获。未来 MCP 在自己的入口完成输入校验并使用同一核心语义；没有真实复用前不预建校验抽象。

### QR-03：可读优先

使用明确命名、类型标注和少量具名数据类型；函数职责集中，预期错误明确。根据实际职责拆分模块，不按行数或通用架构模板拆分。

### QR-04：控制复杂度

以 [AGENTS.md](../../AGENTS.md) 的用户硬规则控制复杂度。首版使用具体 SQLite 实现、初版建表和普通事务，不预建版本兼容或迁移机制。Module 拆分服从实际职责；内部无独立职责的文件可以合并，公共接口保持清楚。

### QR-05：验证可观察行为

优先使用临时真实 SQLite 验证共用接口，通过少量 CLI 场景验证输入输出。显式触发和上下文资料身份通过接入说明与人工跨 agent 场景验收。只记录实际执行的结果。

## 6. 首版范围之外

- 完整聊天采集、导入、监控和原始消息索引。
- 自动摘要服务、向量数据库、自动召回、记忆权重和自动内容合并。
- 多用户权限系统、跨机器同步、远程服务和 agent 自动调度。
- 网页工作台、复杂搜索和跨会话统计。
- MCP server 的实现；未来加入时补充入口契约与验收，核心语义沿用本规格。

## 7. 完成条件

FR-01 至 FR-08 和 QR-01 至 QR-05 有对应的实现或使用约定，并通过 [验收场景](acceptance.md)。文档存在、静态校验通过和自动测试通过均不能单独替代真实跨 agent 交接演示。
