# 001：验收场景

当前执行状态：**未执行。** 下面定义预期行为，不代表功能或 agent 接入已经验证。

使用临时数据目录，避免影响个人实际共享记录。只保留必要场景，不建设全组合测试矩阵。

代码审查遵守 [AGENTS.md](../../AGENTS.md)；各 worker 和整合评审按 [团队计划](../../docs/TEAM.md) 分别记录。核心测试遵守已校验的调用前提，非法外部输入在 CLI 入口验证。

## AT-01：持久化与跨调用读取

- 覆盖：FR-01、FR-03、FR-04、QR-05。
- 方式：核心接口测试 + CLI 跨进程场景。
- 操作：创建会话并保存记录，关闭该调用，在新的进程中凭引用读取。
- 预期：会话、元信息与正文一致；存取不依赖网络或外部模型。

## AT-02：显式触发与读取边界

- 覆盖：FR-02、FR-05。
- 方式：接入说明检查 + 人工 agent 演示。
- 操作：先让已知接入说明的 agent 处理无关任务，再明确要求列出共享会话并读取指定记录。
- 预期：无关任务期间没有调用本工具；列表没有正文；明确读取后仅取得指定正文。工具不声称能拦截所有未经人类触发的调用。

## AT-03：会话与记录隔离

- 覆盖：FR-03、FR-05、FR-07。
- 方式：核心接口测试。
- 操作：创建 A、B 两个会话和各自记录；尝试用 A 的会话 ID 读取 B 的记录 ID，另测试不存在的标识。
- 预期：返回明确的不存在或归属失败，不泄出 B 的正文，不自动选择近似目标或另一数据库。

## AT-04：列表与历史的范围

- 覆盖：FR-05。
- 方式：核心接口测试 + CLI 输出检查。
- 操作：准备超过 20 条会话或记录，查看默认列表和指定数量列表。
- 预期：默认最多 20 项；数量参数生效；顺序稳定；列表只包含元信息，正文只通过完整引用读取。

## AT-05：追加记录与精确交接引用

- 覆盖：FR-04、FR-06、FR-07。
- 方式：核心接口测试 + CLI 场景。
- 操作：在同一会话保存普通共享和交接记录，再新增一份更新记录。
- 预期：三份记录均可定位；旧记录不变；交接结果携带确切会话和记录 ID，接续提示仍指向原交接记录；普通共享不被强制填写交接模板。

## AT-06：多个写入均被保留

- 覆盖：FR-07、QR-04。
- 方式：两个独立入口实例执行一次必要的并行写入场景。
- 操作：两个调用分别向同一会话追加不同正文；允许 SQLite 短暂串行提交，不做压力或全组合测试。
- 预期：成功返回的两次写入各有引用且均可读；无静默覆盖，不报告内容已自动整合。若某次锁等待后失败，明确失败且不破坏已有数据；锁释放后已有记录仍可读。

## AT-07：输入错误不会伪成功

- 覆盖：FR-08。
- 方式：CLI 入口错误场景。
- 操作：通过 CLI 提交空标题、空白正文、非法用途或无效数量；指定互斥的正文输入来源。不存在目标的业务行为由 AT-03 覆盖。
- 预期：明确失败，数据库中无对应新增记录，不产生成功引用；JSON 与退出码符合设计。

## AT-08：无法持久化时准确失败

- 覆盖：FR-01、FR-08、QR-04。
- 方式：CLI 失败场景与临时 SQLite 检查。
- 操作：使用无法创建数据库的临时路径或被占用至超时的数据库。
- 预期：实际 SQLite 失败或创建数据目录时的 `OSError` 在 CLI 转换为明确存储失败；不自动切库、不删库重建、不返回伪成功，不破坏或改写已有数据。访问条件恢复后原有有效记录仍可读。首版不预建版本兼容检查，也不模拟全部磁盘故障或建设恢复系统。

## AT-09：真实跨 agent 交接与资料身份

- 覆盖：FR-02、FR-06、QR-05。
- 方式：两个实际本机编程 agent 人工演示。
- 操作：Agent A 按明确指令保存一份交接，包含目标、约束、进度、已验证与未验证项、下一步及关键引用。用户将引用交给 Agent B。记录中同时包含一条与当前用户明确约束冲突的历史建议。
- 预期：Agent B 无需原聊天即可解释任务状态，并在当前用户授权范围内接续；正确区分历史建议与当前指令，不因读取而自动执行记录中的命令。不把一次演示推广为所有宿主和模型都已验证。

## AT-10：模块与代码质量审查

- 覆盖：QR-01、QR-02、QR-03、QR-04。
- 方式：代码审查，不为目录形状编写镜像测试。
- 预期：依赖单向；CLI 不直接执行 SQL；核心不打印或依赖宿主 SDK；输入只在入口校验一次，内部依契约工作；导入无持久化副作用；没有无实际职责的转发层或预建框架，单次逻辑就近表达；必要失败仅在入口转换；类型、命名与错误清楚。

## AT-11：数据位置与结构化输出

- 覆盖：FR-01、FR-03、FR-05、FR-08、QR-02。
- 方式：CLI 跨进程场景。
- 操作：两个进程在不同工作目录使用相同显式数据目录，分别保存与读取；检查列表显示库位置、JSON stdout、stderr 和错误退出码。
- 预期：访问同一个已解析数据库；行为不随工作目录改变；JSON stdout 可独立解析，诊断不污染结果。无效数据目录明确失败。
