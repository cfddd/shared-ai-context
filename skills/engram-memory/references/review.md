# 证据复核与修订

只在用户明确要求复核、纠错或整理记忆时使用，范围限于当前任务或指定主题。

用户仅要求复核时，只报告发现和证据缺口，不写数据库。用户明确要求写回整理或纠正结果时，已授权按 [主 Skill 的准入与保存操作](../SKILL.md) 更新，无需例行再确认。

1. 定位相关条目，读取完整正文，明确本次复核的具体结论；搜索预览只用于定位。
2. 核对与该结论直接相关的必要原证据。证据锚点使用已有的会话及轮次、日期与用户反馈、命令及实际结果、提交与相关文件等定位信息，说明它支持或推翻了什么。资料路径只说明来源；执行成功须有实际执行结果。分清实际观察与其解释，取不到的信息不补造。
3. 按下表给出结论。来源不可访问时保留原引用并指出缺口，依照主 Skill 的读取规则判断，不把反复出现当作新证据。
4. 仅复核时报告结果；明确授权更新且有有效变化时，同 topic 保存完整当前结论，保留其他有效内容及其锚点和条件。仅被旧结论使用的锚点随原生旧版本保留；无变化则不重写。

## 复核结果

结果只针对本次被复核的具体结论，未复核的内容不连带改变状态。这是正文中的简短约定，不是记录级状态机，普通记忆无需补齐模板。

| 结果 | 判定条件 | 报告及已授权更新 |
| --- | --- | --- |
| 维持 | 证据支持原结论和适用条件 | 报告依据；正文无需变化时不重写 |
| 修订 | 证据支持纠正、补充或缩小原结论范围 | 简述修订原因，同 topic 保存完整当前结论，保留其他有效信息 |
| 待复核 | 证据缺失、不可访问或存在未解决冲突 | 指出具体缺口；召回时保持待确认表述，不作为已证实规则使用 |
| 已否定 | 有足以推翻原结论的证据 | 同 topic 保留原误判简述、否定原因、证据锚点和已知替代结论；替代未知时明确说明 |

缺少证据不能直接判为已否定。已否定条目保留简短否定说明，后续召回先呈现否定信息与替代结论，不继续沿用旧做法；详细旧正文由 Engram 版本机制保留，不增加归档或删除操作。

复核输出采用以下格式，按需要补充适用条件或缺口：

```text
复核结果：维持／修订／待复核／已否定
结论：本次复核后的判断
依据：证据锚点，以及它支持或推翻了什么
```

多 Agent 按条目分工；同一 topic 交给一个维护者汇总，避免并发覆写。此入口由本次用户指令触发，不在后台运行，也不收集全量会话日志。
